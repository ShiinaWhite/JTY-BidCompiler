### 验收闸门（Gate）：做不到就不往下走

1. **五要素判例必须全对**：满足口径的合同 PASS，对象/性质不满足的合同全部 FAIL。
   → 已达成（见测试报告 §4）。
2. **不得误报已闭环项**：资格业绩、2023/2024/2025 审计报告不得出现在缺失清单。
   → 已达成。
3. **每条判定必须带原文引用**：满足判定至少 5 条证据引用。
   → 已达成（测试 `test_every_pass_has_quoted_evidence`）。
4. **判定词封闭**：不得出现"可能满足""大概率满足"等模糊结论。
   → 已达成（测试 `test_verdict_vocabulary_is_closed`）。

## 第二阶段：MVP-6～9（Word 自动编译）

**前置条件**：第一阶段闸门全部通过，且用**第二个真实招标项目**复跑一遍
（避免把一个项目的特例当成通例）。

### MVP-6 商务章节生成
- 生成：投标函、报价表骨架（价格列留空避免代填）、保证金页、偏差表、
  资格证明文件、公司简介、财务状况页、业绩信息统计表（Word 表 + 可编辑 xlsx 双份）。
- 关键约束：**能自动填的只有招标文件里能确定的事实**（项目名、编号、保证金金额、服务期）；
  报价/税率/人员/签章一律留空白并登记为待办。

### MVP-7 技术方案模块
- 服务范围/内容/依据/目标、服务机构与岗位职责、服务方案、HSE 措施、质量措施、
  检修机械工具、售后服务 —— 对应技术分 50 分的 7 个评分项。
- 素材来源：历史标书可复用章节 + 项目化改写（本项目的设备清单、电压等级、工期）。
- **禁止虚构**：设备、人员、业绩一律来自素材库；缺失即登记待办。

### MVP-8 Word 装配
必须复用的长文档经验（详见架构设计 §6）：
- media **原始字节直通**（101MB/193 图的文档不能重新编码图片）；
- 扫描件 DrawingML 旋转属性原样携带；
- 目录只用 Word 更新，**不用 LibreOffice 另存**；
- 分节与页脚：封面无页码、正文重新起算；
- 表格跨页重复标题行、标题不与证据图分离；
- 全链路 SHA256 冻结。

### MVP-9 PDF / 版式 QA
- 导出 PDF（注意：100MB 级文档 COM 导出可能 >15 分钟无产出，需超时与降级策略）；
- 逐项核对：页数、空白异常页、标题孤悬、长图跨页切断、页脚连续、证据图与标题同页。

## 第三阶段：适配器与规模化

1. **Paperless adapter**：实现 `PaperlessMaterialRepository`（映射方案已在类文档中写死），
   届时素材来源从本地目录切到 Paperless REST，业务规则零改动。
2. **扫描件 OCR**：业绩合同/证件是扫描件，当前素材 manifest 里的 `evidence_spans`
   是**人工核验转录**。要让编译器端到端跑通，必须补 OCR（本地、离线、可核对），
   并把 OCR 文本与页码一起存进 `evidence_spans`。
3. **多项目 profile**：把首个项目的字段锚点推广为"招标文件模板族"
   （各招标平台 / 通用范本），新项目只需新增 profile。

## 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 招标文件版式差异大 | 字段/要求抽不到 | 抽取器输出 `extraction_issues` 并显式告警；新项目先跑 `parse-tender` 看命中率 |
| 素材 manifest 靠人工维护 | 判定质量取决于 manifest 质量 | manifest 由已核验核验表生成；OCR 接入后改为自动抽取 + 人工确认 |
| 判定口径变化（如"维护框架下的检修"是否算） | 结论翻转 | 口径写在 `rules/*.json` 且进版本库；改口径=改文件+改测试，可追溯 |
| 大文档 Word/PDF 处理 | 导出失败、内存暴涨 | media 字节直通；导出走独立超时进程；必要时分册导出 |
| 误报稀释 QA 价值 | 公司忽略整张表 | 误报比漏报更优先修；`allow_context` 机制已用于压制合法用法 |
| 越界自动填写 | 合规风险 | 报价/人员/签章一律不自动填，只输出待办 |

## 明确不做（至少本阶段不做）

- 复杂 Web 前端、用户系统、数据库集群、微服务、AI 聊天界面；
- 自动提交投标、自动填真实报价、自动虚构人员；
- 调用付费 API、上传公司资料到第三方。
